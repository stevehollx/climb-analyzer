## ✅ Root Cause Identified

**Date**: 2025-11-19

### Issue Found
The filename pattern in `parse_analysis_filename()` didn't handle the new naming format with version and error counts.

**Old Pattern** (line 232):
```python
pattern = r"(.+)_climbs_(all|paved|gravel|dirt)_(basic|fiets|pdi)_(\d{4}-\d{2}-\d{2})(?:-(\d+))?\.(\w+)"
```

This matched: `Luxembourg_climbs_all_basic_2025-11-19.xlsx`
But NOT: `Luxembourg_climbs_all_basic_2025-11-19_v2.1.0_e0000.xlsx` ❌

**New Pattern** (updated):
```python
pattern = r"(.+)_climbs_(all|paved|gravel|dirt)_(basic|fiets|pdi)_(\d{4}-\d{2}-\d{2})(?:_v[\d.]+_e\d+)?(?:-(\d+))?\.(\w+)"
```

This now matches BOTH formats ✅

### Why Luxembourg Didn't Delete Files
The debug output showed:
```
[DEBUG] is_update: True
[DEBUG] cache_info['xlsx_files']: []
[DEBUG] cache_info['csv_file']: Luxembourg_errors_all_basic_2025-11-19.txt
```

**Explanation**:
- Only a txt file existed in the cache (no xlsx files)
- This was likely the first xlsx upload, or old xlsx files were manually deleted
- Since there were no xlsx files to delete, the deletion was correctly skipped
- The fix will prevent this issue when actual replacement uploads occur

### Testing
The next time you upload a **replacement** for an existing xlsx file (with version/error in filename), the old files should be:
1. Detected by the updated pattern
2. Listed in `cache_info['xlsx_files']`
3. Deleted before uploading new version
4. Shown in PR description under "Files Removed"
